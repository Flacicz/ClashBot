# Database Architecture

## Overview

Система использует SQLite в качестве основной базы данных.

База данных предназначена для хранения:

* актуального состояния кланов и игроков;
* истории изменений состава клана;
* периодических снимков состояния клана и игроков;
* данных клановых войн;
* данных лиги клановых войн (CWL);
* данных рейдовых выходных;
* истории отправленных уведомлений;
* настроек подписок Telegram-чатов.

Архитектура хранения построена вокруг разделения данных на несколько логических контекстов.

---

# Database Philosophy

Система использует гибридную модель хранения данных.

## Master Data

Содержит редко изменяемые сущности.

Назначение:

* хранение канонической информации;
* обеспечение ссылочной целостности;
* использование в качестве корневых сущностей доменной модели.

Таблицы:

* clans
* players

---

## Membership History

Содержит историю нахождения игроков в кланах.

Назначение:

* отслеживание вступлений и выходов;
* анализ длительности пребывания игрока;
* определение новичков и ушедших игроков.

Таблицы:

* clan_memberships

---

## Snapshot Storage

Содержит периодические снимки состояния.

Назначение:

* хранение исторической статистики;
* построение аналитических отчетов;
* сравнение состояний во времени.

Таблицы:

* clan_snapshots
* player_snapshots

Снимки создаются каждые 30 минут.

---

## Event Storage

Содержит завершенные игровые события.

Назначение:

* хранение истории войн;
* хранение истории CWL;
* хранение истории рейдов;
* построение отчетности.

Таблицы:

* wars
* war_clans
* war_members
* attacks
* cwl_seasons
* cwl_season_members
* clan_raids
* player_raid_snapshots

---

## Integration Storage

Содержит данные интеграций и доставки уведомлений.

Назначение:

* защита от повторной отправки уведомлений;
* управление подписками;
* подготовка к мультиклановой архитектуре.

Таблицы:

* notifications
* telegram_chats
* clan_subscriptions

---

# Domain Contexts

## Clan Context

Основной контекст системы.

Отвечает за:

* информацию о клане;
* историю состояния клана;
* управление составом участников.

Таблицы:

* clans
* clan_snapshots
* clan_memberships

---

## Player Context

Отвечает за хранение игроков и их истории.

Таблицы:

* players
* player_snapshots

---

## War Context

Содержит данные обычных клановых войн.

Используется как для регулярных войн, так и для войн внутри сезона CWL.

Таблицы:

* wars
* war_clans
* war_members
* attacks

Агрегат:

War
├── WarClan
├── WarMember
└── Attack

Таблица wars является корнем агрегата.

Все остальные сущности существуют только в рамках конкретной войны.

---

## CWL Context

Содержит данные лиги клановых войн.

Таблицы:

* cwl_seasons
* cwl_season_members

Особенность архитектуры:

CWL не имеет собственной модели войны.

Войны CWL сохраняются в таблицу wars и отличаются только типом войны.

Структура выглядит следующим образом:

CWL Season
└── Season Members
└── Wars

Это позволяет использовать единую модель войны для всех режимов игры.

---

## Raid Context

Содержит данные рейдовых выходных.

Таблицы:

* clan_raids
* player_raid_snapshots

Агрегат:

ClanRaid
└── PlayerRaidSnapshot

---

## Notification Context

Содержит информацию об отправленных уведомлениях.

Таблицы:

* notifications

Основная задача:

* обеспечение идемпотентности системы уведомлений.

Каждое отправленное уведомление регистрируется в базе данных.

Повторная отправка одного и того же события запрещается.

---

## Subscription Context

Подготавливает систему к поддержке нескольких кланов и Telegram-чатов.

Таблицы:

* telegram_chats
* clan_subscriptions

Связи:

Clan
↔ ClanSubscription
↔ TelegramChat

Один клан может иметь несколько подписчиков.

Один Telegram-чат может быть подписан на несколько кланов.

---

# Table Descriptions

## clans

Справочная таблица кланов.

Содержит актуальную информацию о клане.

Характеристики:

* редко изменяется;
* используется как корневая сущность большинства запросов.

---

## players

Справочная таблица игроков.

Содержит актуальную информацию об игроке.

Характеристики:

* редко изменяется;
* используется как корневая сущность для истории игрока.

---

## clan_memberships

История членства игроков в кланах.

Каждая запись представляет отдельный период пребывания игрока в клане.

Позволяет определить:

* текущий состав;
* историю состава;
* новичков;
* ушедших игроков;
* продолжительность пребывания.

Текущий участник определяется по отсутствию даты выхода.

---

## clan_snapshots

Периодические снимки состояния клана.

Используются для:

* аналитики;
* построения исторических графиков;
* анализа развития клана.

---

## player_snapshots

Периодические снимки состояния игрока.

Используются для:

* анализа прогресса;
* отслеживания трофеев;
* отслеживания пожертвований;
* отслеживания изменений ратуши.

---

## wars

Корневая сущность клановой войны.

Содержит:

* идентификатор войны;
* тип войны;
* состояние войны;
* временные параметры;
* итоговый результат.

---

## war_clans

Информация об участниках войны.

Содержит:

* домашний клан;
* противника;
* статистику сторон.

---

## war_members

Участники конкретной войны.

Содержит:

* состав войны;
* позиции игроков;
* итоговую статистику.

---

## attacks

Все атаки войны.

Содержит:

* атакующего;
* защитника;
* количество звезд;
* процент разрушения.

Является основной таблицей для анализа эффективности игроков.

---

## cwl_seasons

Сезоны лиги клановых войн.

Содержит:

* идентификатор сезона;
* параметры сезона;
* информацию о группе.

---

## cwl_season_members

Ростер сезона CWL.

Содержит список игроков, зарегистрированных на сезон.

Ростер фиксируется отдельно от составов конкретных войн.

---

## clan_raids

Рейдовые выходные.

Содержит:

* параметры рейда;
* итоговую статистику;
* результаты рейдового уикенда.

---

## player_raid_snapshots

Активность игроков в рамках рейда.

Содержит:

* количество атак;
* заработанный капитал;
* индивидуальную статистику.

---

## notifications

Журнал отправленных уведомлений.

Используется для:

* защиты от дубликатов;
* обеспечения идемпотентности.

---

## telegram_chats

Telegram-чаты системы.

Содержит информацию о каналах доставки уведомлений.

---

## clan_subscriptions

Связующая таблица между кланами и Telegram-чатами.

Используется для реализации мультиклановой архитектуры.

---

# Data Flow

Каждые 30 минут запускается цикл синхронизации.

1. Получение данных через Clash of Clans API.
2. Преобразование JSON в доменные модели.
3. Сохранение справочных данных.
4. Обновление состава клана.
5. Создание снимков состояния.
6. Сохранение данных войн.
7. Сохранение данных CWL.
8. Сохранение данных рейдов.
9. Генерация доменных событий.
10. Проверка уведомлений.
11. Отправка сообщений в Telegram.
12. Регистрация отправленных уведомлений.

---

# Transaction Strategy

Все операции записи выполняются внутри транзакций.

Используется TransactionGuard.

Гарантии:

* атомарность;
* автоматический rollback при ошибках;
* автоматический commit при успешном завершении.

---

# Migration Strategy

Управление схемой базы данных выполняется через MigrationManager.

Основные задачи:

* создание новой базы данных;
* применение миграций;
* хранение версии схемы;
* обновление структуры между версиями приложения.

---

# Future Evolution

Текущая версия системы ориентирована на обслуживание одного клана.

Архитектура базы данных уже подготовлена для поддержки:

* нескольких кланов;
* нескольких Telegram-чатов;
* независимых подписок;
* пользовательских настроек уведомлений;
* полноценной мультиклановой платформы.
