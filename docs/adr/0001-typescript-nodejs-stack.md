# ADR-0001: Технологический стек TypeScript и Node.js 24 LTS

Переносим ClashBot с C++20 (CMake, vcpkg, MSVC/Ubuntu builder) на TypeScript поверх Node.js 24 LTS, чтобы ускорить цикл разработки, упростить сопровождение и сделать проект предсказуемым для автономной агентной разработки без потери функционального паритета.

## Решение

Целевой стек TypeScript-реализации:

- **Среда выполнения и Docker**: Node.js 24 LTS; продовый образ строится на базе `node:24-slim`.
- **Язык и система модулей**: TypeScript в режиме ESM (`"type": "module"`) со строгой проверкой типов (`strict: true`, `noUncheckedIndexedAccess: true`) и проверкой типов через `tsc --noEmit`.
- **Менеджер пакетов**: `pnpm`.
- **SQLite**: `better-sqlite3` с параметризованным SQL в репозиториях без ORM, чтобы сохранить прямой контроль над транзакциями, `PRAGMA` и существующей схемой БД (см. [ADR-0002](0002-single-loop-better-sqlite3.md) и [ADR-0004](0004-sqlite-drop-in-compatibility.md)).
- **HTTP-клиент для Clash of Clans API**: встроенный `fetch` / `undici` с таймаутом 20 секунд и поддержкой `AbortSignal`. Для локального SSH-туннеля (`api.use_tunnel: true`) отключение проверки TLS выполняется через отдельный `undici` `Agent`, привязанный строго к туннельному клиенту, и никогда не включается глобально для процесса.
- **Telegram**: `grammY` для входящего бота и тонкий `TelegramGateway` поверх `grammY` `Api` для исходящей доставки из outbox (см. [ADR-0003](0003-grammy-outbox-delivery.md)).
- **Валидация внешних границ**: `zod` для `config.json`, переменных окружения (`.env`), каталога видео-гайдов, ответов Clash of Clans API и десериализации `event_payload` доменных событий.
- **Логирование**: `pino` со строгим выводом в `stdout` (структурированный JSON в контейнере под управлением ротации Docker; читаемый формат для локальной разработки). Отдельная файловая ротация логов в приложении не реализуется.
- **Тестирование и качество кода**: Vitest для unit- и integration-тестов (на настоящей SQLite без моков БД), ESLint (`typescript-eslint`) и Prettier.

На период поэтапного переноса TypeScript-версия разрабатывается рядом с C++-реализацией (side-by-side) в том же репозитории, используя существующие SQL-миграции как единый источник правды до финального переключения (`cutover`).

## Рассмотренные альтернативы

- **ORM поверх SQLite (Prisma / Drizzle)**: отклонены, так как усложняют двустороннюю совместимость с 12 существующими SQL-миграциями, скрывают управление `BEGIN IMMEDIATE` / `PRAGMA foreign_keys` и добавляют лишний слой генерации поверх простых таблиц.
- **Встроенный `node:sqlite`**: отклонён на пользу зрелого и стабильного `better-sqlite3` с проверенной поддержкой синхронных транзакций в production.
- **Сохранение файловой ротации логов (`logs/bot.log`)**: отклонено, поскольку в Docker-окружении логи собираются и ротируются самим Docker из `stdout`, а дублирующая запись в файл усложняет эксплуатацию и права на тома.

## Последствия

- Сборка и запуск тестов сводятся к `pnpm` + Vitest + `tsc --noEmit` + ESLint без длительной перекомпиляции C++ и установки vcpkg.
- Нативная зависимость `better-sqlite3` требует совместимой сборки под целевую платформу (в том числе `node:24-slim` в Docker), что проверяется в CI.
- Локальная конфигурация и `.env` не меняются; существующий том `/app/logs` перестаёт быть обязательным после переключения на TS-образ.
