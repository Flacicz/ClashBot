# Telegram-интеграция

## Роли Telegram в проекте

Telegram используется в двух независимых направлениях:

1. NotificationService отправляет отчёты, напоминания и системные сообщения подписанным назначениям.
2. TelegramBotService получает входящие сообщения и callback-запросы, показывает меню гайдов и управляет подписками
   кланов.

Бот не предоставляет произвольный запрос аналитики. Источник игровых данных — только фоновая синхронизация с Clash of
Clans API.

## Конфигурация

В config.json используется секция telegram:

    {
      "telegram": {
        "attack_guides_path": "resources/telegram/attack_guides.json"
      }
    }

Путь разрешается относительно текущего рабочего каталога процесса. В Docker ресурс находится в
/app/resources/telegram/attack_guides.json.

Обязательный секрет — TELEGRAM_TOKEN. Он передаётся через окружение или .env рядом с config.json. Токен не должен
храниться в config.json, исходниках, Dockerfile или архиве образа.

Каталог гайдов загружается при старте. Ошибка открытия файла, некорректный JSON, отсутствие массива guides или неверный
тип обязательного поля останавливают запуск приложения.

## Long polling

TelegramBotService работает в отдельном потоке и вызывает getUpdates:

- offset начинается с 0;
- timeout запроса — 2 секунды;
- разрешены update-типы message и callback_query;
- после обработки корректного update_id offset становится update_id + 1;
- ошибка Telegram API или сети логируется, затем выполняется пауза 1 секунда;
- stopLoop() прерывает ожидание через condition_variable.

Webhook в приложении не настраивается: для работы этого режима бот должен получать обновления через getUpdates.

Из message обрабатываются только команды. Из callback_query сначала вызывается answerCallbackQuery, затем разбираются
данные callback и обновляется интерфейс.

## Команды

Поддерживаемые команды:

    /start
    /link #CLAN_TAG
    /unlink #CLAN_TAG

Парсер команд:

- принимает текст, начинающийся с /;
- удаляет суффикс @bot_username;
- приводит имя команды к нижнему регистру;
- разделяет остальные токены пробелами;
- Telegram-команды, отличные от start, link и unlink, игнорируются сервисом.

Тег клана принимает форму #TAG или TAG. Нормализация:

- длина от 3 до 15 символов;
- регистр не важен;
- разрешены только символы 0, 2, 8, 9, P, Y, L, Q, G, R, J, C, U, V;
- результат хранится и передаётся как #TAG в верхнем регистре.

Команды link и unlink требуют ровно один аргумент. Ошибка формата отправляется в тот же чат и, если команда пришла из
forum topic, в ту же тему.

## Аудитории и права

Тип Telegram-чата определяет аудиторию:

| Тип чата | Аудитория | Кто может link/unlink |
| --- | --- | --- |
| private | management | пользователь личного чата |
| group | players | administrator или creator |
| supergroup | players | administrator или creator |
| остальные | не поддерживается | никто |

Для group и supergroup сервис вызывает Telegram getChatMember. Бот должен иметь права, достаточные для проверки
статуса участника. Обычный member не может изменить подписку.

Такое соответствие означает, что личный чат получает управленческие отчёты, а группа — обычные сообщения для игроков.
Две аудитории для одного назначения можно создать вручную в SQLite, но одна команда link создаёт только аудиторию,
соответствующую типу текущего чата.

## Подключение клана

В нужном чате отправьте:

    /link #2PPLQ

В одной транзакции сервис:

1. создаёт или повторно включает запись clans;
2. сохраняет telegram_chats с chat_id, message_thread_id и названием;
3. создаёт clan_subscriptions с соответствующей audience;
4. фиксирует commit;
5. отправляет подтверждение пользователю.

Если клана ещё нет, имя временно устанавливается в Pending synchronization. Следующий цикл ClanInfoService получает
полную информацию через API. Уже существующая подписка не дублируется.

В forum topic используется message_thread_id из исходного message. Для общего чата значение равно 0. Уведомления
отправляются с тем же идентификатором, поэтому остаются в выбранной теме.

## Просмотр и отключение

В главном меню доступны:

- Подключить клан — экран с инструкцией /link;
- Мои кланы — список кланов текущего chat_id, message_thread_id и audience;
- Отключить клан — список подписок и выбор одной из них;
- Помощь — /link, /unlink и правила доступа.

Команда:

    /unlink #2PPLQ

Удаляется только подписка текущего назначения и текущей аудитории. Если в назначении не осталось подписок, строка
telegram_chats удаляется. Если у клана не осталось ни одной подписки, clans.tracking_enabled устанавливается в 0.
История клана, войн и рейдов не удаляется.

Кнопка отключения выполняет те же проверки прав, что и команда. Callback без выбранного клана сначала показывает список
подписок; callback с тегом удаляет выбранную запись.

## Главное меню и callback-навигация

/start без аргументов отправляет inline-клавиатуру:

- 🎥 Гайды по атакам, callback guides:townhalls;
- 🔗 Подключить клан, callback clans:link;
- 📋 Мои кланы, callback clans:list;
- ❌ Отключить клан, callback clans:unlink;
- ❓ Помощь, callback help:main.

Кнопка возврата в меню использует callback menu:start. Другие callback-команды:

| Callback | Действие |
| --- | --- |
| guides:townhalls | список TH7–TH18 |
| guides:townhall:<townHall> | стратегии выбранной ратуши |
| guides:strategy:<townHall>:<armyId> | гайды стратегии |
| guides:guide:<townHall>:<guideId> | отправка выбранного видео |
| clans:link | инструкция подключения |
| clans:list | список подписанных кланов |
| clans:unlink | список или отключение подписки |
| help:main | справка |

Callback-данные разбираются по разделителю двоеточие. Пустые части и данные короче двух частей отклоняются.
Неизвестные команды не выполняют действий.

## Каталог видео-гайдов

Файл resources/telegram/attack_guides.json содержит объект с массивом guides. Одна запись имеет:

| Поле | Обязательность | Назначение |
| --- | --- | --- |
| id | обязательно | уникальный идентификатор гайда |
| army_id | обязательно | идентификатор стратегии |
| army_title | опционально | название стратегии, по умолчанию army_id |
| variant_id | обязательно | идентификатор варианта |
| variant_title | обязательно | название варианта |
| title | обязательно | отображаемый заголовок |
| town_halls | обязательно | массив уровней ратуши |
| youtube_url | обязательно | ссылка на видео |
| sort_order | опционально | порядок, по умолчанию 0 |
| enabled | опционально | доступность, по умолчанию true |

Пустой town_halls означает доступность для любой поддерживаемой ратуши. Сейчас интерфейс валидирует диапазон TH7–TH18.
Каталог сортируется стабильно по sort_order.

AttackGuideCatalog:

1. читает и валидирует весь JSON при старте;
2. исключает записи с enabled = false;
3. строит уникальный список стратегий для выбранной ратуши;
4. возвращает гайды выбранной стратегии;
5. находит активный гайд по id;
6. не изменяет SQLite.

После выбора гайда бот отправляет две обычные HTML-сообщения: название со ссылкой и отдельное сообщение с кнопками
возврата. Видео не скачивается и не проксируется приложением.

## Доставка уведомлений

TelegramNotifier знает только chat_id, message и message_thread_id. TelegramApiClient отправляет sendMessage с:

- parse_mode = HTML;
- chat_id;
- text;
- message_thread_id, если он не равен 0.

NotificationService выбирает подписчиков из clan_subscriptions по audience. Ошибка отправки не ломает доставку в
остальные назначения: она логируется с chat_id и тегом клана.

Для итогов, сравнений и reminders проверяется таблица notifications до отправки и запись создаётся только после успешного
ответа Telegram. Изменения состава, роли и системные события такой защиты не имеют.

## Получение chat_id и message_thread_id

Для ручной настройки SQLite нужно получить update через Telegram getUpdates. В объекте message:

- message.chat.id — chat_id;
- message.message_thread_id — идентификатор forum topic, если сообщение отправлено в тему;
- для общего чата используйте message_thread_id = 0.

Не публикуйте URL getUpdates с настоящим токеном бота. Для штатного подключения предпочтительнее использовать /link,
который сам сохраняет назначение в транзакции.

## Тестирование

Telegram-компоненты тестируются без сети:

- TelegramCommandsTests — парсинг команд и тегов;
- TelegramCallbackDataTests — callback-данные и контекст;
- TelegramKeyboardsTests — JSON inline-клавиатур;
- AttackGuideCatalogTests — схема каталога, сортировка и фильтрация;
- TelegramValidationTests — диапазон ратуш;
- TelegramBotServiceIntegrationTests — команды, права, темы, polling, ошибки и callback-сценарии.

FakeTelegramApiClient записывает отправленные и отредактированные сообщения, callback-ответы и вызовы getUpdates.
