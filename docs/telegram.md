# Telegram-интеграция

## Назначение

Telegram в проекте используется в двух независимых режимах:

* `NotificationService` отправляет отчеты и напоминания подписанным чатам и темам;
* `TelegramBotService` принимает сообщения и callback-запросы от пользователей и показывает интерактивное меню
  видео-гайдов.

Интерактивное меню не изменяет подписки, состав клана или другие данные SQLite.

## Конфигурация

Параметры находятся в секции `bot` файла `config.json`:

```json
{
  "bot": {
    "telegram_token": "<TELEGRAM_BOT_TOKEN>",
    "attack_guides_path": "resources/telegram/attack_guides.json"
  }
}
```

`attack_guides_path` разрешается относительно текущего рабочего каталога процесса. В Docker используется путь
`/app/resources/telegram/attack_guides.json`.

Каталог загружается во время запуска. Ошибка открытия файла, некорректный JSON или неправильный тип поля приводят к
ошибке запуска приложения.

## Пользовательский сценарий

Команда `/start` отправляет главное меню. Дальше пользователь последовательно выбирает:

1. ратушу TH7–TH18;
2. стратегию;
3. видео-гайд.

После выбора бот отправляет название и ссылку на YouTube. Inline-кнопки позволяют вернуться к списку гайдов,
стратегий или в главное меню.

Поддерживаемые callback-команды:

```text
menu:start
guides:townhalls
guides:townhall:<town_hall>
guides:strategy:<town_hall>:<army_id>
guides:guide:<town_hall>:<guide_id>
```

`parseCallbackData` выполняет только структурный разбор строки: выделяет команду из первых двух частей и сохраняет
остальные части как аргументы. `TelegramBotService` дополнительно проверяет количество аргументов, диапазон ратуши и
наличие стратегии или гайда в каталоге.

## Формат каталога гайдов

Корневой JSON-объект содержит массив `guides`:

```json
{
  "version": 1,
  "guides": [
    {
      "id": "th7_zap_dragons_azilee",
      "army_id": "zap_dragons",
      "army_title": "Зап-драконы",
      "variant_id": "classic",
      "variant_title": "Классический вариант",
      "title": "Название видео",
      "town_halls": [7],
      "youtube_url": "https://www.youtube.com/watch?v=...",
      "sort_order": 10,
      "enabled": true
    }
  ]
}
```

Обязательные поля записи: `id`, `army_id`, `variant_id`, `variant_title`, `title`, `town_halls`, `youtube_url`.

Необязательные поля:

* `army_title` — по умолчанию используется `army_id`;
* `sort_order` — по умолчанию `0`;
* `enabled` — по умолчанию `true`.

Гайды сортируются по `sort_order` со стабильным порядком одинаковых значений. Отключенные записи не показываются.
Пустой массив `town_halls` означает, что гайд доступен для любой ратуши.

## Реализация

`TelegramApiClient` выполняет вызовы Telegram Bot API для отправки, редактирования и получения сообщений, а также для
подтверждения callback-запросов. `TelegramBotService` получает обновления через long polling в отдельном потоке.

Чистая логика вынесена в отдельные компоненты:

* `TelegramCallbackData` — разбор callback-данных и контекста;
* `TelegramKeyboards` — построение JSON inline-клавиатур;
* `TelegramValidation` — проверка номера ратуши;
* `AttackGuideCatalog` — загрузка, фильтрация и поиск гайдов.

Для отправки отчетов и интерактивного меню используется один Telegram bot token, но эти два потока обработки логически
разделены.

## Тестирование

Unit-тестами покрыты чистые компоненты Telegram:

* разбор корректных и некорректных callback-данных;
* разбор callback-контекста Telegram JSON;
* структура всех inline-клавиатур;
* диапазон и некорректные значения ратуши;
* загрузка, сортировка, фильтрация и поиск записей каталога, включая ошибки структуры и типов JSON.

Тесты запускаются через стандартный `ClashBotTests` и CTest, как описано в основном [`README.md`](../README.md).
