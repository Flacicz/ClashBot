# Границы MVP и вектор развития ClashBot

Документ фиксирует согласованный состав **MVP** (на базе исследования [competitors.md](research/competitors.md) и [platform-and-user-signals.md](research/platform-and-user-signals.md)), фильтр существующих GitHub Issues и список отложенных идей для этапа пост-MVP.

Текущее реализованное состояние системы (AS-IS) описано в [`docs/roadmap.md`](roadmap.md). Термины — в [`GLOSSARY.md`](../GLOSSARY.md).

---

## 1. Цели, формат запуска и критерий успеха MVP

- **Продуктовая суть MVP**: надёжный сбор основных данных клана из CoC API + удобный просмотр текущего состояния пользователями в Telegram + автоматические отчёты, нарушения и напоминания.
- **Формат запуска**: hosted Telegram-бот на собственном сервере (снятие главного барьера CoC API — VPS и статического IPv4). Исходный код на этапе MVP остаётся открытым; вопрос выделения приватных модулей (Open Core) отложен до появления уникальной логики после MVP.
- **Рынок и язык**: только RU/СНГ (без i18n в MVP).
- **Монетизация в MVP**: отсутствует (бесплатный пилот, с соблюдением Supercell Fan Content Policy и размещением обязательного дисклеймера).
- **Критерий успеха MVP**: бот стабильно, без ручных вмешательств в БД и рестартов, обслуживает **5–10 активных отслеживаемых кланов** (включая внешние) минимум **3–4 недели** (полный игровой цикл: обычные КВ + ЛВК + 3–4 рейда), а лидеры и участники реально пользуются отчётами и командами просмотра.

## 2. Новые продуктовые возможности MVP

### 2.1. Интерактивные команды просмотра (строго из локальной SQLite)

Все команды дублируются кнопками в inline-меню `/start` и читают данные **только из SQLite** (без прямых запросов к CoC API по команде пользователя), явно указывая время последнего обновления данных (например, «обновлено 7 мин назад»):

- `/war` — текущая обычная КВ: счёт звёзд и `%`, оставшееся время, список участников с оставшимися атаками;
- `/cwl` — текущий сезон ЛВК: активный раунд, счёт, кто ещё не отбился;
- `/raid` — текущий рейдовый уикенд: добыча золота, разрушенные районы, кто ещё не использовал все атаки;
- `/clan` — карточка **отслеживаемого клана** и состав; если для **подписки** включена категория «Дисциплина и аналитика», доступен быстрый вызов сводки надёжности состава.

**Поведение при нескольких кланах в одном Telegram-назначении**:

- 1 подключённый клан — команда отвечает сразу;
- >1 подключённых кланов — без аргументов выводится короткий выбор клана inline-кнопками; с аргументом (`/war #TAG`) — мгновенный ответ по указанному клану.

### 2.2. Оперативные напоминания со списком не отбившихся

- Внутри `war_reminder` (обычные КВ и ЛВК) и `raid_reminder` выводится список участников, у которых остались неиспользованные атаки (по игровым никам; при совпадении ников — с тегом игрока).

### 2.3. Пресеты подписки и 5 категорий уведомлений ([ADR-0006](adr/0006-subscription-presets-and-notification-categories.md))

- Замена жёсткой привязки `group → players` / `private → management` на модель одной **подписки** с 5 переключаемыми **категориями уведомлений** (`Итоги и сравнения`, `Напоминания`, `Кадры`, `Дисциплина и аналитика`, `Системные оповещения`) и 3 **пресетами** (`Игроки`, `Руководство`, `Всё вместе`).
- Позволяет подключать офицерские групповые чаты и форумные темы для разбора дисциплины, получать итоги в личке и отключать шумные кадровые сообщения в общем чате.

### 2.4. Минимальные настройки и онбординг для внешних кланов

- **Правило «первая атака не по зеркалу»**: настраиваемый переключатель (вкл/выкл). Для **новых** кланов по умолчанию **`выкл`**; для **уже существующих** в БД кланов при миграции сохраняется **`вкл`** ради обратной совместимости. Пропуски атак (`0` атак и `1/2` атаки) считаются **нарушением** всегда.
- **Часовой пояс**: явное отображение и возможность выбрать смещение (по умолчанию `UTC+3`).
- **Диагностика приватного War Log (`isWarLogPublic = false`)**: при `/link` и в статусе клана бот явно предупреждает, что журнал войн закрыт и обычные КВ недоступны через CoC API (при этом ЛВК и рейды работают).
- **Дисклеймер Fan Content Policy**: упоминание в `/help` и описании бота, что проект неофициальный и не связан с Supercell.

## 4. Идеи и вектор развития после MVP

Долгосрочное видение, продуктовые принципы и порядок стратегических направлений (Руководство → Игроки → Боевая аналитика) вынесены в [`docs/strategy.md`](strategy.md). Ниже — список конкретных отложенных технических и продуктовых идей, сознательно не включённых в MVP:

1. **Аналитический «цифровой зам главы» (главная Северная звезда)**:
   - система принятия и поддержки управленческих решений вместо ручных таблиц: кого брать в основной состав ЛВК и кого ротировать, кому справедливо выдать бонусные медали ЛВК, автоматическая система страйков и рекомендаций по предупреждению/исключению, чёрный список с заметками руководства.
2. **Привязка игроков `Telegram ↔ player_tag` и адресные `@mention`-пинги**:
   - связывание Telegram-профилей с игровыми аккаунтами (включая мультиаккаунты/твинки и опциональную верификацию через `POST /players/{playerTag}/verifytoken`);
   - адресные пинги в напоминаниях, персональная статистика (`/me`).
3. **Игры кланов (Clan Games)**:
   - официального endpoint'а в CoC API нет; реализация через периодический опрос `GET /v1/players/{playerTag}` в окно 22–28 числа и расчёт дельты накопительного достижения `"Games Champion"` (с учётом ограничений перелива сверх 4000, переходов между кланами и отсутствия базового снапшота при позднем подключении).
4. **Расширение гибкости, скорости и интерфейсов**:
   - ускорение цикла синхронизации во время активных войн (например, до 5 минут);
   - более тонкая настройка правил нарушений, порогов напоминаний и отдельных типов уведомлений;
   - Telegram Mini App (TMA) / веб-дашборд для удобной работы с таблицами на 30–50 участников и планировщиком ЛВК;
   - поиск произвольного игрока (`/player #TAG`), архив войн, бронь целей (war caller), локализация EN (i18n).
5. **Монетизация и экономика**:
   - проработка устойчивой модели (донаты, Creator Code, облачный хостинг / масштабирование / коучинг / Open Core) с учётом ограничений Supercell Fan Content Policy.
