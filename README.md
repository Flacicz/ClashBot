# ClashBot

ClashBot — автономный сервис, который получает данные из официального API Clash of Clans и помогает отслеживать ключевые
показатели активности клана и его участников.

Сервис предназначен для глав и соруководителей кланов. Он упрощает контроль активности игроков, позволяет наблюдать за
их прогрессом и помогает принимать решения по управлению кланом. ClashBot уже поддерживает одновременное отслеживание
нескольких кланов и отправку отчётов в несколько Telegram-чатов и тем форумных групп, хотя сейчас используется только
для одного клана.

ClashBot регулярно собирает информацию о кланах и сохраняет её в базе данных. На основе полученных данных сервис
формирует удобные отчёты и отправляет их подписанным участникам и руководству через Telegram. Это автоматизирует
выявление нарушений и избавляет глав и соруководителей от необходимости вручную проверять активность каждого участника.

> Проект находится в активной разработке. Сервис уже собирает большую часть доступной информации о кланах, однако в
> отчётах пока используется только часть этих данных.

## Основные возможности

- **Войны кланов** — уведомление о начале войны, напоминания за 6 часов и за 1 час до окончания, отчёт о результате и статистике атак, а также отдельный управленческий отчёт о пропусках, игроках с одной атакой и атаках не по зеркалу.
- **Рейды столицы клана** — уведомления о начале рейдовых выходных, напоминания за 48, 24, 6 и 1 час до окончания,
  отчёт с общей статистикой и лучшими участниками, сравнительный отчёт с предыдущим рейдом и историческим средним,
  а также отдельный отчёт для руководства о неиспользованных атаках.
- **Лига войн кланов** — уведомления о начале, за 6 часов и за 1 час до окончания каждого раунда, результаты
  всех семи раундов и статистика лучших атак, а также отдельный управленческий отчёт о нарушениях раунда.
- **Сравнение войн** — динамика последней войны относительно предыдущей и среднего показателя за предыдущие войны.
- **Надёжность состава** — управленческий отчёт об участии игроков в последних клановых войнах.
- **Аудитории уведомлений** — раздельные Telegram-подписки для игроков и руководства клана.
- **Изменение ролей** — уведомления о повышении и понижении участников внутри клана.
- **Изменение состава** — уведомления о вступивших в клан и покинувших его игроках.
- **Хранение истории** — сохранение полученной информации в базе данных для последующего анализа.
- **Telegram-отчёты** — автоматическая отправка собранной информации в удобном для чтения формате.
- **Интерактивное Telegram-меню** — команда `/start` и навигация по каталогу видео-гайдов для ратуш TH7–TH18.

## Как работает ClashBot

1. При запуске ClashBot получает из базы данных список отслеживаемых кланов.
2. Сервис последовательно собирает через API Clash of Clans сведения о составе кланов, войнах, Лиге войн кланов и
   рейдовых выходных. После завершения полного цикла ClashBot делает паузу на 30 минут, а затем запускает следующую
   синхронизацию.
3. Полученные данные преобразуются, сравниваются с уже имеющейся информацией и сохраняются в базе данных SQLite.
4. При обнаружении значимых изменений или наступлении контрольного времени сервис формирует Domain Events. Для обычной
   клановой войны и каждого раунда CWL это уведомление о начале, напоминание за 6 часов и напоминание за 1 час до
   окончания. Для рейдовых выходных отправляются уведомления о начале, за 48, 24, 6 и 1 час до окончания. После
   завершения событий формируются подробные отчёты с результатами и сравнительной динамикой для игроков и отдельные
   отчёты о нарушениях и надёжности состава для руководства.
5. Готовые отчёты и напоминания отправляются во все Telegram-назначения соответствующей аудитории, подписанные на
   соответствующий клан. Назначение состоит из ID чата и, при необходимости, ID темы форума. ClashBot учитывает уже
   отправленные уведомления и не отправляет одно и то же событие повторно в одно и то же назначение.

## Технологии

- **C++20** — основной язык и стандарт разработки.
- **CMake** — конфигурация и сборка проекта.
- **vcpkg** — установка зависимостей в manifest mode.
- **SQLite** — хранение актуальных и исторических данных.
- **CPR и libcurl** — выполнение HTTP-запросов.
- **nlohmann/json** — обработка данных в формате JSON.
- **fmt** — форматирование строк, даты и времени.
- **spdlog** — логирование работы приложения.
- **Docker** — сборка и запуск сервиса в изолированном окружении на базе Ubuntu 24.04.
- **Стандартная библиотека C++** — многопоточность и синхронизация фоновых процессов.

### Внешние сервисы

- **Clash of Clans API** — получение игровых данных.
- **Telegram Bot API** — отправка отчётов и уведомлений.

## Установка и запуск

ClashBot можно запускать локально на Windows для разработки или разворачивать в Docker на Linux-сервере.

### Требования

#### Проверенный Windows build/test baseline

- Windows 10 x64;
- MSVC 19.50 x64;
- подготовленный `x64 Native Tools` terminal;
- Ninja 1.12.1;
- CMake 3.24 — объявленная проектом минимальная версия; текущий baseline проверен с CMake 4.4.1;
- Git для клонирования репозитория;
- vcpkg с доступным CMake toolchain; зависимости собираются для triplet `x64-windows`.

#### Получение build-зависимостей

Зависимости проекта объявлены в `vcpkg.json`: `cpr`, `fmt`, `spdlog`, `nlohmann-json` и `sqlite3`. При конфигурации с
vcpkg toolchain менеджер пакетов автоматически устанавливает отсутствующие зависимости в build tree. Ручной вызов
`vcpkg install` для каждого пакета не требуется.

Для первой конфигурации чистого build tree нужен доступ к реестру и исходным архивам vcpkg. Последующие сборки
используют локальный кэш пакетов.

#### Runtime requirements

- для запуска нужен файл `config.json`;
- пути из конфигурации и каталоги для runtime-файлов, включая `data` и `logs`, должны быть доступны для записи;
- заранее созданная SQLite-база не требуется: ClashBot создаёт файл базы и применяет миграции при запуске;
- для реальной работы с внешними сервисами нужны Supercell API token и Telegram bot token.

#### Условные инструменты

- при `"use_tunnel": true` нужны WSL, SSH-клиент, доступ к Linux-серверу и настроенный туннель;
- Docker нужен только для сценария развёртывания в контейнере;
- SQLite client нужен только для ручного администрирования базы и не требуется для запуска приложения или
  автоматического применения миграций.

### Клонирование репозитория

```bash
git clone https://github.com/Flacicz/ClashBot.git
cd ClashBot
```

### Конфигурация

Создайте в корне проекта файл `config.json`:

```json
{
  "api": {
    "supercell_token": "<CLASH_OF_CLANS_API_TOKEN>",
    "use_tunnel": true,
    "tunnel_base_url": "https://localhost:8080/v1",
    "base_url": "https://api.clashofclans.com/v1"
  },
  "database": {
    "path": "data/database2.sqlite",
    "migrations_path": "src/database/migrations"
  },
  "bot": {
    "telegram_token": "<TELEGRAM_BOT_TOKEN>",
    "attack_guides_path": "resources/telegram/attack_guides.json"
  }
}
```

Параметр `use_tunnel` определяет способ подключения к API Clash of Clans:

- `true` — запросы отправляются через SSH-туннель;
- `false` — используется прямое подключение через `base_url`.

> Файл `config.json` содержит секретные токены и не должен добавляться в Git.

### Получение идентификаторов Telegram-чата и темы

1. Добавьте Telegram-бота в нужный чат.
2. Отправьте в чат сообщение или команду для бота.
3. Выполните запрос к методу [`getUpdates`](https://core.telegram.org/bots/api#getupdates):

```text
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getUpdates
```

4. Для обычного чата найдите в полученном JSON объект `chat` и его поле `id`:

```json
{
  "message": {
    "chat": {
      "id": -1000000000000
    }
  }
}
```

Значение поля `id` является идентификатором Telegram-чата.

Если нужно отправлять сообщения в отдельную тему форумной группы, `chat.id` остаётся общим для всей группы. В том же
объекте `message` найдите поле `message_thread_id`:

```json
{
  "message": {
    "chat": {
      "id": -1000000000000,
      "title": "Clan group"
    },
    "message_thread_id": 456,
    "text": "тест"
  }
}
```

Чтобы получить ID нужной темы, добавьте бота в группу, убедитесь, что это форумная группа, откройте нужную тему и
отправьте в ней сообщение. Значение `message_thread_id` из этого обновления является ID темы. Для общего чата
используйте `message_thread_id = 0`.

Отдельная Telegram-группа и тема внутри форумной группы — разные случаи:

- у отдельной группы свой `chat_id`;
- у темы тот же `chat_id`, что и у группы, но свой `message_thread_id`.

ClashBot передаёт `message_thread_id` в Telegram Bot API только для тем. Для общего чата поле не передаётся.

> Не публикуйте адрес запроса с настоящим токеном Telegram-бота.

### Интерактивное Telegram-меню

Команда `/start` открывает главное меню бота. В нём доступен каталог видео-гайдов по атакам:

1. выбрать ратушу от TH7 до TH18;
2. выбрать стратегию;
3. выбрать конкретный гайд;
4. получить название и ссылку на видео в YouTube.

Кнопки навигации позволяют вернуться к списку гайдов, стратегий или в главное меню. Каталог загружается из файла,
указанного в `bot.attack_guides_path`. Формат каталога и текущие записи находятся в
[`resources/telegram/attack_guides.json`](resources/telegram/attack_guides.json). Интерактивное меню не изменяет
подписки и настройки клана: управление кланами и Telegram-назначениями по-прежнему выполняется через SQLite.

### Локальная сборка на Windows

Установите vcpkg и укажите путь к его корневому каталогу:

```powershell
$env:VCPKG_ROOT = "C:\path\to\vcpkg"
```

Перед первым локальным запуском из корня проекта создайте каталоги для базы данных и журналов:

```powershell
New-Item -ItemType Directory -Force data, logs
```

Канонические команды сборки выполняются из корня проекта в подготовленном `x64 Native Tools` terminal. Для clean
configure используйте новый пустой каталог `cmake-build-release`. Переданный toolchain обнаружит `vcpkg.json` и
автоматически установит зависимости для выбранного triplet.

```powershell
cmake -S . -B cmake-build-release -G Ninja `
  -DCMAKE_BUILD_TYPE=Release `
  -DVCPKG_TARGET_TRIPLET=x64-windows `
  -DCMAKE_TOOLCHAIN_FILE="$env:VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake"
```

Соберите проект:

```powershell
cmake --build cmake-build-release
```

CLion можно использовать как необязательную альтернативу с отдельным CMake profile, но terminal-команды выше являются
канонической проверкой и не зависят от cache или скрытых настроек IDE.

#### Тесты

Соберите test target и запустите зарегистрированные CTest tests из того же build tree:

```powershell
cmake --build cmake-build-release --target ClashBotTests
ctest --test-dir cmake-build-release --output-on-failure
```

CTest автоматически обнаруживает отдельные тесты GoogleTest для утилит, аналитики, форматтеров отчётов и чистых
Telegram-компонентов: парсеров callback-данных, клавиатур, валидации ратуши и каталога гайдов. При успешном запуске
CTest сообщает `100% tests passed`; при ошибке `--output-on-failure` показывает вывод упавшего теста.

#### Диагностика

При сборке MSVC targets `ClashBot` и `ClashBotTests` получают target-scoped warning level `/W4`. Предупреждения не
настроены как ошибки: `/WX` не включён.

Для отладочной сборки используйте отдельный build tree, не переиспользуя Release cache:

```powershell
cmake -S . -B cmake-build-debug -G Ninja `
  -DCMAKE_BUILD_TYPE=Debug `
  -DCMAKE_TOOLCHAIN_FILE="$env:VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake"
cmake --build cmake-build-debug
```

#### Безопасный локальный smoke run

Для проверки startup без настоящих секретов используйте новую пустую базу без отслеживаемых кланов и локальный
`config.json` с фиктивными непустыми токенами и loopback URL:

```json
{
  "api": {
    "supercell_token": "DUMMY_SUPERCELL_TOKEN",
    "use_tunnel": false,
    "tunnel_base_url": "http://127.0.0.1:1/v1",
    "base_url": "http://127.0.0.1:1/v1"
  },
  "database": {
    "path": "data/smoke.sqlite",
    "migrations_path": "src/database/migrations"
  },
  "bot": {
    "telegram_token": "DUMMY_TELEGRAM_TOKEN",
    "attack_guides_path": "resources/telegram/attack_guides.json"
  }
}
```

Не добавляйте локальный `config.json`, настоящие токены или созданную базу в Git. Запускайте приложение из корня
проекта, чтобы относительные пути к конфигурации, базе, миграциям и журналу разрешались от одного working directory:

```powershell
.\cmake-build-release\ClashBot.exe .\config.json
```

Успешный smoke startup должен сообщить о загрузке конфигурации, применении миграций, нуле отслеживаемых кланов,
инициализации сервисов и завершении startup. Это не проверяет рабочий цикл с внешними API. Для остановки нажмите
`Ctrl+C` и убедитесь, что приложение сообщило о штатном завершении работы.

#### Опциональный SSH-туннель

Туннель требуется только при `"use_tunnel": true`. Настройте `scripts/startTunnel.sh`, указав адрес Linux-сервера и
пользователя для SSH-подключения, затем запустите его через WSL:

```powershell
wsl bash ./scripts/startTunnel.sh
```

### Развёртывание на Linux-сервере

Из-за ограниченных ресурсов сервера Docker-образ собирается локально, сохраняется в TAR-архив и передаётся на сервер
через SCP.

Для серверного запуска измените конфигурацию:

```json
{
  "api": {
    "supercell_token": "<CLASH_OF_CLANS_API_TOKEN>",
    "use_tunnel": false,
    "tunnel_base_url": "https://localhost:8080/v1",
    "base_url": "https://api.clashofclans.com/v1"
  },
  "database": {
    "path": "/app/data/database2.sqlite",
    "migrations_path": "/app/migrations"
  },
  "bot": {
    "telegram_token": "<TELEGRAM_BOT_TOKEN>",
    "attack_guides_path": "/app/resources/telegram/attack_guides.json"
  }
}
```

Соберите Docker-образ на локальной машине:

```powershell
docker build -t clashbot:latest .
```

Сохраните образ в TAR-архив:

```powershell
docker save -o clashbot.tar clashbot:latest
```

Подготовьте каталоги на сервере:

```bash
ssh <SSH_USER>@<SERVER_IP> "mkdir -p ~/clashbot/data ~/clashbot/logs"
```

Передайте образ и конфигурацию:

```powershell
scp .\clashbot.tar <SSH_USER>@<SERVER_IP>:~/clashbot/
scp .\config.json <SSH_USER>@<SERVER_IP>:~/clashbot/config.json
```

Подключитесь к серверу:

```bash
ssh <SSH_USER>@<SERVER_IP>
```

Загрузите Docker-образ:

```bash
docker load -i ~/clashbot/clashbot.tar
```

Запустите контейнер:

```bash
docker run -d \
  --name clashbot \
  --restart unless-stopped \
  -v "$HOME/clashbot/config.json:/app/config.json:ro" \
  -v "$HOME/clashbot/data:/app/data" \
  -v "$HOME/clashbot/logs:/app/logs" \
  clashbot:latest
```

SQL-миграции уже находятся внутри Docker-образа и применяются автоматически при запуске приложения.

Проверить состояние контейнера можно командой:

```bash
docker ps
```

Для просмотра журналов контейнера используйте:

```bash
docker logs clashbot
```

### Добавление клана и Telegram-назначения

После первого запуска ClashBot автоматически создаст базу данных и применит миграции.

Перед ручным изменением базы данных остановите локальное приложение или Docker-контейнер:

```bash
docker stop clashbot
```

Откройте созданную базу данных:

```bash
sqlite3 ~/clashbot/data/database2.sqlite
```

Добавьте отслеживаемый клан:

```sql
INSERT INTO clans (tag, name)
VALUES ('#CLAN_TAG', 'Clan name');
```

Добавьте общий Telegram-чат:

```sql
INSERT INTO telegram_chats (chat_id, message_thread_id, title)
VALUES (-1000000000000, 0, 'Telegram group');
```

Для темы форумной группы укажите её `message_thread_id` вместо `0`:

```sql
INSERT INTO telegram_chats (chat_id, message_thread_id, title)
VALUES (-1000000000000, 456, 'War reports');
```

Свяжите клан с общим чатом или темой:

```sql
INSERT INTO clan_subscriptions (clan_tag, chat_id, message_thread_id, audience)
VALUES ('#CLAN_TAG', -1000000000000, 456, 'players');
```

В запросе используется четвёртый столбец `audience`:

- `players` — отчёты и напоминания для участников клана;
- `management` — отчёты о нарушениях, надёжности состава и системные сообщения для руководства.

Для общего чата в последнем запросе используйте `message_thread_id = 0`. Если одна группа или тема должна получать
обе аудитории, добавьте две записи с одинаковыми `clan_tag`, `chat_id` и `message_thread_id`, но разными значениями
`audience`.

Выйдите из SQLite:

```sql
.quit
```

Снова запустите контейнер:

```bash
docker start clashbot
```

При локальной разработке запустите приложение повторно обычной командой.

Список отслеживаемых кланов загружается при запуске ClashBot. Во время первого цикла синхронизации сервис получит
остальные сведения о добавленном клане через API Clash of Clans.

## Ограничения

- Управление кланами и Telegram-подписками выполняется вручную через SQLite.
- Подписка разделяется только на аудитории `players` и `management`; отдельная настройка категорий отчётов пока не реализована.
- Критерии выявления нарушений пока нельзя настраивать отдельно для каждого клана.
- Telegram-бот поддерживает `/start` и интерактивный каталог видео-гайдов; команды просмотра статистики и управления
  подписками пока не реализованы.
- Временные напоминания реализованы для обычных клановых войн, раундов CWL и рейдовых выходных.
- Напоминания обрабатываются в рамках цикла синхронизации, который обычно выполняется раз в 30 минут, поэтому время
  доставки может отличаться от контрольного момента.
- В отчётах задействована только часть собираемых данных.
